# HUD 自由布局交互方案（待实施）

日期：2026-11-15。基于 v0.17.1 源码及本轮用户反馈“目前这一版看上去不错”。用户明确本轮“先确认交互方案，保持 Unity 关闭”。本文仅定义下一版交互；未修改应用、启动Unity、构建APK或访问Quest。外观认可不代表五项已知交互缺陷已通过验收。

## 1. 统一成“移动—放置方式—自动跟随”

保留现有左侧设置分类。由“布局 → 编辑 HUD 布局”进入明确的编辑模式，选择要调整的面板；所选面板显示顶部抓取条、底部放置选项，其他面板保持原位。退出编辑后收起这些控件。

```text
正在编辑：运动面板
┌──────────────────────────────────────┐
│  ⠿ 捏住此处移动       [图钉：未固定]  │
├──────────────────────────────────────┤
│                                      │
│             原有 HUD 内容            │
│                                      │
├──────────────────────────────────────┤
│ 放置方式   [环境 ✓]  [手部]  [面前]   │
│ 跟随：柔和（默认） / 快速             │
│ [撤销]       [复位此 HUD]      [完成] │
│                            100%  ↘   │
└──────────────────────────────────────┘
```

这是结构示意，不是实际运行截图。图钉只在“环境”下显示；“柔和/快速”仅在环境未固定时显示或从其简短设置入口展开。普通使用时不常驻编辑框。图钉配文字状态，避免用户猜图标；悬停、选中、抓住三种反馈可辨，但不依赖颜色独自表达。

产品文案用“放置方式”，不把Unity渲染Layer暴露给用户。

## 2. 三种选项、四种行为

| 放置方式 | 图钉 | 实际行为 | 拖动后保存什么 |
|---|---|---|---|
| 环境 | 已固定 | 留在当前场景位置；转头、走动不自动跟随 | 当前世界位置与朝向 |
| 环境 | 未固定 | 默认采用柔和跟随：小幅转头不追逐，较大转头后稍等再平滑跟上；平移随观察者移动 | 相对延迟跟随参考方向的自定义偏移 |
| 手部 | 不显示 | 跟随左手，保留用户调整的相对位置；不是只能放一个预设落点 | 相对左手参考面的偏移 |
| 面前 | 不显示 | 固定在视野中的某个位置；随头部立即移动，不使用环境模式的延迟 | 相对观察者视角的偏移 |

“面前”不必是正中央，可以调整到视野右上、左下等位置。“环境未固定”也能位于右上方，但转头后它会延迟跟上，两者差异应在选项说明中讲清楚。

**图钉控制自动跟随，不是编辑锁。** 已固定的HUD仍能由用户主动抓住顶部移动；松手后固定在新位置。切换图钉时不瞬移、不改大小，也不悄悄改变用户摆好的位置。取消固定后采用柔和跟随作为默认；若用户选过快速，再次切换图钉应保留其偏好。

“环境固定”本版只承诺当前运行/追踪空间中的固定，不等同于跨重启保存真实房间的空间锚点。

## 3. 抓取与位置记忆规则

1. **先选对象，再移动。** 对象名称和选中边框明确当前调整的是主面板还是小型读数。数据页、地图页、设置页属于同一主面板，共享位置。
2. **指向顶部抓取条，捏住后拖动，松手放置。** 保持原抓取偏移，不把面板中心突然吸到射线上；保持既有自由射线，不加自动瞄准。进入抓取后由同一只手持有，另一只手不抢占。
3. **底部选项决定参考位置，拖动只修改该位置下的偏移。** 在手部或面前模式松手，即使没有命中任何空间落点框，也不能自动改成环境固定。旧的“拖到三个框才算停靠”不再作为主要操作路径。
4. **摆到右上方就记住右上方。** 环境未固定时，跟随结束后仍回到用户选定的偏移；收起再打开、切换主卡内容也保持。只有明确点击“复位此HUD”才恢复默认。
5. **操作时面板稳定。** 抓取和滑块捕获期间，自动运动不能推动面板去点击静止手指。滑块取值、释放、边界采用统一参考坐标；失追踪/失焦取消未完成的操作，恢复后需释放再触发。
6. **切换放置方式是显式动作。** 第一次切到手部时移往可达的初始手部位置；之后恢复该HUD在该方式下上次的位置。短暂过渡要可预期，切到未追踪的手部时提示“先抬起左手”，不凭空放到旧位置。
7. **撤销针对当前HUD的完整上一步。** 位置、方式、图钉、距离与缩放必须一致恢复；不可只恢复旧Transform。拖动未完成时失效则回到抓取前；普通点击不能同时触发拖动提交。
8. **完成退出编辑。** 松手即在本次会话内生效，完成用于退出编辑；复位只作用于选中的HUD，和“恢复全部设置”分开。

跨应用重启的布局保存单独列为后续能力，不把本次会话记忆描述为已实现持久化。若以后加入保存：只保存确认完成的布局，不保存正在捏合/拖动状态；环境世界锚点需单独设计重定位规则。

## 3.1 右下角等比缩放（本轮补充，待实施）

用户提出像手机小窗一样拖动右下角，沿对角线按比例调节大小。推荐将它作为独立于顶部移动把手的第二种操作：**顶部移动整块HUD，右下角调整大小**。只在编辑模式、对象已选中时显示右下角斜向箭头，指向时提示“捏住缩放”。

- **等比变化：** 指向右下角并捏住，向右下拉大，向左上缩小；松手确认。整个HUD内容、文字、图标保持宽高比，不单独拉宽或拉高。角标显示相对默认尺寸的百分比，如100%。
- **固定对角：** 推荐左上角作为缩放支点，缩放时左上角在当前操作平面不动，右下角随拖动变化；面板中心自然随尺寸调整。这样不会一边缩放一边整块漂走。
- **只算面板平面内的拖动：** 捕获开始时记录操作平面、支点、初始尺寸和抓取偏移；将指针移动投影到该平面，并沿对角方向求统一缩放比例。无须手指走出完美45度轨迹，也不能把手前后移动误当成改变HUD距离。射线近乎平行或交点无效时保留最后有效预览，不跳变。
- **稳定与互斥：** 缩放期间稳定操作面，暂停该HUD自动跟随；同一时刻只允许一只手执行移动、缩放或滑块操作中的一种。失追踪、失焦或退出编辑时，取消未确认的缩放并恢复抓取前完整状态；恢复后释放再重新抓取。
- **尺寸与距离分开：** 缩放不改变放置方式、图钉状态或面板深度。保留现有按距离补偿的基准尺寸，另存用户缩放倍率；以后调距离、切页或收起重开不能把倍率重置为100%。手部/面前模式仍记录其参考系内的完整位置和尺寸状态。
- **限制与反馈：** 设置最小/最大尺寸，防止缩到无法阅读、按钮难点或大到占满视野；到边界停止增长并提示，不反向翻转。编辑把手的命中区域保留可操作下限。具体范围以Quest阅读和手部触碰测试决定，本轮不把任意倍率写成已验证阈值。
- **撤销与复位：** 一次捏住至松手只产生一次可撤销操作，撤销恢复尺寸和支点变化带来的位置；“复位此HUD”恢复该HUD默认位置与100%尺寸，不影响其他HUD或天空。

主面板与小型读数分别保存缩放倍率。延续当前方案的会话内记忆范围；不由此承诺跨应用重启或跨房间空间锚点保存。

新增验收：右下拉大/左上缩小且宽高比恒定；左上支点不漂；首帧抓取不跳；尺寸上下限反馈明确；纯深度移动不改变距离设置；图钉/类别不变；距离变化仍保留用户倍率；追踪丢失取消、撤销恢复完整位置与尺寸；主卡和小读数互不影响。Unity和Quest均待实施后验证。

## 4. 各块HUD的范围

| 对象 | 本方案关系 |
|---|---|
| 主面板：数据/地图/设置内容 | 一套位置状态；内容切换不重新定位 |
| 小型读数 | 使用同样的编辑方式，但独立保存自己的方式、图钉和偏移；目前代码还只有左/右/隐藏，需要接入 |
| 手背 HUD/HIDE 入口 | 继续作为轻量开关，不跟主面板一起被搬走 |
| 前方备用打开/召回入口 | 保留独立的可达位置，防止把主面板放手上后丢追踪就无法找回 |
| 天空地图 | 仍是独立被动环境层；不加入抓取条、图钉或三种停靠，不随HUD编辑改变 |

因此可以分别把主面板放到右上、小读数放到左下，或把其中一个放到手边；这些位置互不覆盖。首次主面板仍可沿用“环境＋未固定＋柔和跟随”，小读数沿用其当前可见性，编辑不应默默开启隐藏对象。

## 5. 从两个参考项目借鉴什么

本轮已读取公开源码；以下为参考项目事实，其余Quest操作规则是结合用户提议作出的设计选择，尚未经过Quest验证。

| 参考 | 已读实现 | 借鉴到本项目 |
|---|---|---|
| SkyHanni `GuiPositionEditor` | 单独编辑界面、悬停框/名称、点击记录抓取位置、释放；支持重置默认位置/比例 | 明确编辑态、明确当前对象、抓取不跳变、复位单个HUD |
| SkyHanni `Position` | x/y/scale为序列化字段；点击/抓取为临时状态 | 把布局数据与临时输入状态分开；不能仅凭字段推定其具体落盘时机 |
| Skyblocker `WidgetsConfigurationScreen` | 区分悬停与选中框；保存相对抓取点，释放后停止；退出时序列化保存 | 用户能看懂“指到/选中/抓住”，位置不因下一次打开而丢失 |
| Skyblocker 对齐辅助 | 按住Shift才启用布局吸附，可对齐边缘/其他组件 | 后续若加对齐，做成主动辅助；不改变射线方向，本轮不增加自动吸附 |

## 6. 对应现有Unity的改动点（供后续实施）

- 保留内部 `World / Follow / View / Hand` 实现映射，外部只呈现“环境/手部/面前＋图钉”。顶部把手和单手射线捕获可复用，不需要引入Minecraft代码或依赖。
- `AeroWindowLayout`：把放置方式选择与拖动结果分开；为手部增加相对Pose；面前模式自由拖放后继续保持View；统一图钉、距离、召回和撤销的状态来源。
- `HudSoftFollow`：保存延迟参考系与自定义偏移；跟随死区检测“观察者相对参考系转了多少”，不能检测面板是否偏离视线中央，否则右上方布局会被当成误差持续纠正。重开不能调用会清掉偏移的正中复位。
- `AeroCompactHud`：当前直接挂相机，`SetPlacement`写死左/右位置；需接入相同布局规则，但独立存状态，备用入口不搬走。
- 手势和滑块：同时处理已发现的五项P2。优先修近抓跳变、移动误触和滑块参考系；撤销需覆盖新状态；手背门控仍需正面重新武装。

这些是待实现改动，不是本轮已完成功能。

## 7. 验收清单

- 环境固定时转头/走动不自动挪位；主动抓条仍能移动。图钉切换当帧姿态和大小连续。
- 右上方的环境跟随HUD在转头后延迟回到右上方，不回正中央，不因偏置持续漂移；柔和/快速只改变跟随节奏。
- 手部和面前模式拖放后仍保留类别，手/头移动时局部偏移稳定。
- 主卡数据/地图/设置切换、收起/重开保留布局；主卡与小读数独立；天空和备用入口不变。
- 捏合只启动一次抓取；释放、丢追踪、失焦和另一只手竞争处理明确。近距离起抓没有20cm跃迁。
- 触碰和滑块操作不因面板自身运动产生误点、改值或提前提交。
- 改距离、图钉或放置方式之后撤销，大小、位置与状态一致；无可撤销动作时按钮明确禁用。
- 自动检查通过后再做Quest实测：确认可读性、追踪遮挡、延迟跟随手感、头锁定舒适度；不能用Editor结果代替。
