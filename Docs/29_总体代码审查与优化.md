# 总体代码审查与修复 — v0.21.1

What this change does: 本轮检查单用户Quest 2原型的输入、布局、存储、渲染辅助及构建发布链路。以两只手、五个组件、最多12份布局档案为负载边界，修复可复现问题，不进行大规模架构重写。

## Must fix（已修复）

1. **主卡收起后，独立组件失去点击暂停跟随保护**（`Assets/PinchHudExperiment.cs:170`）
   - 功能：近处触碰或保持射线按压时，面板应暂时稳定。
   - 问题：判断仅允许主卡打开，单独显示心率组件时保护失效。新检查在旧代码上实际失败。
   - 修复：把可见独立组件纳入判断，覆盖直接触碰与射线按压。
   - 不修的影响：用户伸手点组件时，窗口会随转头继续移动。

2. **隐藏的跟随面板重新打开时停留在旧位置**（`Assets/HudSoftFollow.cs:50`）
   - 功能：柔和跟随应保留用户选定的相对偏移。
   - 问题：隐藏时跳过位移更新，打开时又清掉积累位移；实测注入移动2米后，窗口仍在原处，误差2米。
   - 修复：隐藏时继续同步跟随面板的平移，环境固定面板保持固定。位置误差小于1mm的回归断言通过。
   - 不修的影响：走动后手背打开HUD可能找不到主卡，只能手动召回。

3. **隐藏手部组件的追踪变化打断另一块窗口的拖动**（`Assets/AeroUI/AeroWindowLayout.cs:343`）
   - 功能：失追踪应取消依赖该追踪的操作。
   - 问题：任一手部组件的追踪变化都会全局清空输入；关闭手部心率组件后，用右手拖主卡，左手丢失追踪会让主卡回弹。旧代码检查实际失败。
   - 修复：只让相关可见窗口的追踪变化清空输入；另一窗口的抓取继续，拥有抓取的手丢失仍取消。
   - 不修的影响：不相关的隐藏组件也能让正常拖动突然失败。

4. **从丢失追踪的手部窗口切出后，放置按钮点不动**（`Assets/AeroUI/AeroWindowLayout.cs:180,330`）
   - 功能：底部环境/手部/面前工具栏复用于选中的窗口。
   - 问题：手部追踪丢失会关闭工具栏碰撞体；换到其他窗口时只换父节点，不恢复碰撞体。旧代码检查实际失败。
   - 修复：共享工具栏单独管理碰撞体，换窗口时按新窗口可用状态同步；回归确认真实射线能命中并切换放置。
   - 不修的影响：按钮外观正常，但射线和食指触碰都无法操作。

## Should fix（已修复）

5. **发布工具没有检查源码清单是否漏项**（`Tools/01_publish_release.py:15`）
   - 功能：确认APK构建时的源码与发布提交一致。
   - 问题：此前只检查清单列出的文件；漏掉新增运行脚本时，其内容从未核验。
   - 修复：先比较Assets/Packages/ProjectSettings/DESIGN完整集合，再逐项验证哈希。新单元检查覆盖漏项、多项、新文件和构建后修改。
   - 不修的影响：不完整的清单可能被误当成完整构建证明。

6. **历史发布审计仍强制要求私有仓库**（`Tools/02_audit_release_history.py:9`）
   - 功能：回读标签、源码与发布安装包摘要。
   - 问题：仓库已经按用户要求公开，原PRIVATE断言会立即终止合法审计。
   - 修复：默认检查PUBLIC，保留显式PRIVATE选项。
   - 不修的影响：现有仓库无法使用该工具核验发布历史。
