# 0.15.0 响应与独立天空修复

用户原话要点：按钮可能很长时间没有响应；天空地图应像PS进天空，地图与HUD布局分开、无额外按钮；HUD的HIDE/SHOW不应开关天空；SOFT FOLLOW和天空不该被留在原处。原聊天01a1ce75-bdbd-7210-b5a2-21520efb5e23与Mostar参考图已重新读取。此前“天空/前方二态互斥、天空固定在打开位置”是旧实现选择，不应作为新要求的验收标准。

## 根因与证据

- 已确认的状态耦合：IsCardOpen包含Sky.Visible；ShowSkyMap关闭主卡；ShowMapDetail/CloseCard隐藏Sky；Recenter优先处理Sky。导致关闭/召回命令作用于另一个图层。
- 已确认的跟随机制：任何手只要悬停按钮，就把outsideTime清零；界限附近反复进出也重置等待；身体横移只用径向距离检测容易漏掉。新增平移跟随、0.32秒柔和转头等待和4度滞回，短暂按压稳定有0.6秒上限，独立手部SKY快捷不冻结主卡。
- 已确认的输入机制：新捏合先于命中到达时，按压边沿被消耗，没有计时延后执行。有效目标当帧立即响应；仅为错开一两帧的真实命中保留最多120毫秒衔接，不吸附射线。界面开关、任一次接受操作、失追踪/失焦清空待确认，避免跨界面误点。
- 已确认的释放风险：max(原生连续值,关节值)+原生bool OR，只要任何一路高位滞留就无法释放。有效关节值优先，输入源切换重新要求释放；测试覆盖原生高位/关节已松开。
- 可减少的每帧工作：原布局Input/LateUpdate和手部快捷重复同步物理；集中查询前同步，缓存状态/组件。原天空大量Image细线改为1个曲面Graphic，916线段，天空总16个Graphic，无按钮/碰撞/GraphicRaycaster。该结构证据不等于Quest实测FPS提升。
- 不将CalculateFingerShapeUncached凭名字判断为GC源：已读已安装XR Hands源码，Pinch路径为结构体与关节距离计算，未发现每次托管数组分配，不虚构原因。

## 新行为

天空默认开启，半透明曲面线网位于前上方约27度、半径20m；随观察者平移，普通转头维持世界朝向。看开超过70度持续0.7秒才以32度/秒缓慢回到前上方，避免留在身后，同时保持与硬性头锁定不同。不是地物真实配准。

HUD的手背HUD/HIDE、数据/地图、关闭/打开、RECENTER、布局复位均不改变天空开关。主卡上方SHOW SKY/HIDE SKY只控制天空；设置原EDIT SKY改为CENTER SKY。天空自身无按钮/把手/窗口停靠。主卡仍可按既有方式拖拽/撤销/复位。

## 验证边界

电脑实际运行时自动检查通过，覆盖30次瞄准后同帧确认、早边沿衔接、不重复/恢复误点、跨窗口丢弃、悬停/长期按压跟随、平移/阈值抖动、Fixed→Soft参考点、天空独立/无输入表面/平移与朝向、原手背/地图/设置/小读数/停靠与20次完整流程。新增要求直接测试，不沿用旧测试的互斥/永久固定结论。
