## 1. 项目是什么

AeroPulse Ultra 的目标是面向骑行、跑步等运动场景的平视运动仪表。本阶段用 **Unity + Meta Quest 2** 制作交互原型，探索怎样在视野内查看运动信息、用手势呼出或收起界面，以及怎样让面板保持容易阅读和操作的位置。

**本次软件成果是可运行、可交互的概念验证。** Quest 2 用来模拟未来眼镜的显示与交互，并不是已经做出了目标重量的智能眼镜实物。当前没有接入真实体征传感器、GPS、蓝牙运动设备或在线导航。

可以直接用于汇报的简述：

> 我们已将运动 HUD 从静态概念推进到 Quest 2 可运行的 Unity 原型，实现了手背入口、运动信息与示意路线、独立天空地图、面板跟随及分类设置。迭代依据来自早期用户试戴反馈和后续编辑器检查。当前重点是修复移动面板下的误触、滑块和布局恢复问题，随后再集中验证头显中的可读性、操作手感与舒适度。

## 2. 已实现的功能

“已实现”表示现有源码与安装包中具备该功能，不等于所有场景都通过实机验收。第 4 节列出的边界缺陷仍待修复。

| 模块 | 当前可以做什么 | 汇报时需要说明的范围 |
|---|---|---|
| 运动 HUD | 显示心率、配速、距离；打开、收起、再次打开 | 142、5:20、3.20 等是固定模拟值，不是实际采集 |
| 手背入口 | 右食指触碰左手手背入口，切换 HUD 显示；可调按钮高度 | 已实现，移动与背侧接近仍有误触边界 |
| 双手交互 | 近处食指直接触碰；远处手部射线指向并捏合；保留真实命中反馈 | 不使用射线自动吸附；最新组合操作仍需 Quest 复测 |
| 前方路线页 | 数据/地图切换，五站示意路线、当前位置/下一站、演示推进与重置 | 不是真实 GPS、路径规划或地物配准 |
| 天空环境地图 | 独立、无按钮的环境地图层；随观察者平移，普通转头保持方向，大幅看开后缓慢回归 | HUD 的收起、数据切换和召回不会关闭天空；早期窗口停靠方案已经被替换 |
| 面板跟随 | 柔和跟随、快速跟随、固定位置；主卡召回；距离设置 | 默认距离 0.65 m，可调 0.55–2.20 m；实际舒适范围待佩戴验证 |
| 分类设置 | 左侧“显示 / 交互 / 布局”分类，右侧具体设置；高度与距离滑块；确认/取消恢复默认 | v0.17.1 最新结构；设置只在当前会话生效，重启不记忆 |
| 小型读数与快捷 | 小型读数可放左侧、右侧或隐藏；可选手部快捷与前方备用入口 | 与详细 HUD、天空层分别管理 |
| 布局编辑 | 显式进入编辑，抓取把手移动，环境/视野/手部停靠，撤销与复位 | 功能已实现；近抓跳变、撤销缩放和手部滑块问题待修 |
| 操作反馈 | 悬停/确认视觉反馈、可选提示音、首次帮助及追踪恢复提示 | 提示音默认关闭；真实反应速度不能用编辑器检查替代 |
| 工程交付 | Unity 源码、版本标签、Android APK、版本校验、操作与迭代文档 | 当前 GitHub 已公开，同学无需启动 Unity 就能阅读和下载素材 |

## 4. 待优化问题与后续顺序

以下五项已在 Unity 生产类的确定性检查中复现，尚未修复；P2 表示应在后续版本处理。复现数值用于解释问题，不是现场误触率或用户实验统计。

| 顺序 | 问题 | 用户会遇到什么 | 下一步修复与验收方向 |
|---|---|---|---|
| 1 | 面板运动可能引发误触 | 手指先靠近后停住，面板再移近，仍会触发按钮 | 区分手指主动前进与面板移动；补“先接近再静止”回归 |
| 2 | 手部停靠滑块参考坐标不一致 | 面板与指尖一起移动，接触位置不变，35 mm 仍可能变成 37 mm，或提前提交 | 稳定操作面，或统一取值/释放/边界坐标；失追踪仍须取消 |
| 3 | 近距离抓取跳变 | 距把手 15 cm 开始抓取时，主卡可能突然跳远约 20 cm | 统一抓取距离与偏移，使首次拖动连续 |
| 4 | 改距离后撤销旧放置会缩小界面 | 距离从 0.65 m 改为 2.20 m 后撤销，主卡可能只剩应有大小的约 30% | 清除失效撤销记录，或完整恢复距离、位置和缩放 |
| 5 | 手背按钮背侧误触 | 手指先经过正面，再绕到背侧进入，仍可能开关 HUD | 越界后重新要求正面接近，并保留释放与恢复保护 |

修复后的集中 Quest 检查：左右手触碰/捏合交接、追踪恢复、手背遮挡与按钮高度、长时间阅读、跟随舒适度、文字清晰度及实际响应。最终性能结论应有设备测量，不能写“卡顿已完全消除”。

视觉质感与配色排在上述稳定性问题之后。用户认可当前设置布局，但偏好早期版本的质感；尚未指定要恢复哪一版，不宜描述为已确定新视觉方案。

## 6. 汇报内容怎样组织

可以按六个问题组织叙述，不要求固定页数：要解决什么运动信息查看问题 → 为什么用Quest验证 → 主卡/手背/天空三类交互做到了什么 → 如何根据反馈迭代到左侧分类设置 → 当前五项问题和验证边界 → 下一步先修稳定性、再做集中试戴。

若只有一分钟：使用主卡图和最新设置图，讲“可运行原型 + 反馈驱动迭代 + 下一轮明确任务”。若现场演示尚未排练，使用已归档截图；不要把未安装的最新版安排成确定能现场完成的演示。

> 中期阶段完成了Unity软件交互原型及版本化交付，已形成手背入口、运动HUD、示意路线、独立天空层和可调设置的组合。早期版本获得了用户短时体验反馈；最新版本完成构建和编辑器检查，尚待集中实机验收。我们已把后续重点收敛到五项可复现的交互边界问题，先提高操作稳定性，再优化视觉质感。
